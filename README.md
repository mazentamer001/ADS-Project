# ADS Project — Event-Driven Gate-Level Logic Simulator and Timing Analyzer

**Course:** CSCE 2200 – Applied Data Structures  
**Project:** Team 10  
**Status:** Milestone 1 data structures + circuit parsing/timing-analysis test suite

## Overview

This project represents digital circuits as directed graphs. A `.net` file declares primary inputs, outputs, gates, propagation delays, and connections. A `.stim` file supplies time-stamped changes to primary inputs. The project includes custom data structures, a netlist parser, combinational-loop detection through topological analysis, critical-path timing analysis, and VCD waveform output.

The application currently supports combinational logic simulation infrastructure and timing analysis. DFF netlists are accepted for structural and timing analysis, but the current simulator does **not** yet implement clocked DFF state updates or a complete levelized/event-driven simulation engine. Do not interpret the counter stimulus as proof of sequential simulation.

## Build and test

Requirements: a C++17 compiler (for example `g++`) and Python 3 for regenerating the two adder netlists.

```bash
make
make test
```

Individual test programs:

```bash
./test_ds
./test_analysis tests
./test_circuits
```

Build the command-line application:

```bash
make sim
```

Run a circuit through parsing, loop checking, timing analysis, and optional VCD input replay:

```bash
./sim tests/full_adder.net tests/full_adder.stim -o full_adder.vcd
```

Generate the 8-bit adder netlists:

```bash
make generate-adders
# or: python3 tools/gen_adders.py tests
```

Clean generated executables and VCD files:

```bash
make clean
```

## Circuit file format

A `.net` file uses one statement per line. `#` starts a comment.

```text
INPUT a b cin
OUTPUT sum cout
XOR x1 2 a b
XOR sum 2 x1 cin
```

Gate statement format is `TYPE name delay input1 [input2]`. Supported combinational gates are `NOT`, `AND`, `OR`, `XOR`, and `NAND`. `DFF` has two inputs: pin 0 is D and pin 1 is CLK. Output declarations create output probes named internally with the `$out` suffix.

A `.stim` file uses:

```text
<time> <primary-input-name> <value>
```

Values are `0`, `1`, `X`, or `Z`. Times must be non-negative and non-decreasing. Several changes may share one timestamp.

## Test coverage

- `tests/test_ds.cpp`: FIFO tie-breaking for equal-time events, HashMap rehash, HashSet insert/remove/clear, and rejection of an already-driven graph pin.
- `tests/test_analysis.cpp`: full-adder critical path, timing on a simple chain, combinational-loop detection, and VCD output behavior.
- `tests/test_circuits.cpp`: full adder, 8-bit ripple adder, 8-bit carry-lookahead adder, structural counter parsing/timing, and rejection of `loop_error.net`.
- `tests/expected/`: reference arithmetic outputs and counter behavior notes for the demo vectors.

The 8-bit adders are generated by `tools/gen_adders.py` to reduce hand-written wiring mistakes.

## Current limitations

- The counter netlist is a structural sequential example. The parser and timing analyzer accept DFFs and treat DFF input edges as sequential boundaries, but DFF state transitions are not simulated.
- The CLI currently reports timing and can replay input events into a VCD file; a complete gate-value simulation requires the simulator modules to be integrated.
- `src/GraphAlgos.cpp` and older duplicate graph-algorithm files in the original archive are not part of the current Makefile build. The active timing analyzer uses its own Kahn topological pass.
